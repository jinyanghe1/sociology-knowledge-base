### 使用方法
1. 安装依赖: `pip install -r requirements-mcp.txt`
2. 配置 Ollama (详见 OLLAMA_SETUP.md)
   ```bash
   ollama serve
   ollama pull nomic-embed-text
   ```
3. 配置 Claude Desktop (详见 CLAUDE_DESKTOP_CONFIG.md)
4. 在 Claude 中调用 tools 进行 RAG 检索

### Workspace（作用域限定）
- `index_folder("/path/to/文件夹/")` → 自动使用文件夹名作为 workspace
- `rag_search("查询", workspace="文件夹名")` → 限定搜索范围
- `list_workspaces()` → 查看所有工作区

### Ollama 配置
- 生产环境 **必须** 安装 Ollama
- 自动检测，无需额外代码配置
- 无 Ollama 时回退到 hash-based（仅开发测试）

## 核心技术栈对比
| 维度 | FastAPI 方案 | MCP 方案 |
|------|-------------|---------|
| 部署 | FastAPI + Streamlit + 多进程 | 单一 MCP Server |
| 依赖 | 20+ 包 (FastAPI/Streamlit/Ollama/LangGraph) | 5-8 包 (mcp + ChromaDB + parser) |
| 客户端 | 自建 Streamlit UI | Claude Desktop / Cursor / kimi |
| 推理能力 | 本地 Ollama (受限) | 云端 Claude/kimi (强大) |
| 维护复杂度 | 高 | 低 |

## 建议
基于 RESEARCH.md 分析，推荐废弃 FastAPI 方案，迁移至 MCP Server 架构：
1. 保留 `backend/vector_store/` 和 `backend/core_logic/parser.py`
2. 新建 `mcp_server/` 目录实现 MCP Server
3. 使用 Claude Desktop 作为前端交互界面

### 问题统计
| 级别 | 数量 | 说明 |
|------|------|------|
| 🔴 CRITICAL | 10 | 可能导致数据丢失或系统崩溃 |
| 🟠 HIGH | 15 | 潜在的性能或安全问题 |
| 🟡 MEDIUM | 23 | 代码质量问题 |
| 🟢 LOW | 15+ | 轻微问题或建议 |

### 关键风险点
1. **线程安全** - `_doc_meta` / `EmbeddingCache` / `fallback_store` 无锁保护
2. **数据一致性** - 索引/删除操作非原子，无回滚机制
3. **内存安全** - 大文件全量读取可能导致 OOM
4. **安全漏洞** - 路径遍历、无文件大小限制
